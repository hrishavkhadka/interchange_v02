# Interchange — Project Context & Handoff

## 1. Project Goal & Vision

A level-based traffic puzzle game built in Godot 4. The player is given entry/exit roads, a demand matrix, a budget, and a time limit. The player builds roads, junctions, interchanges, and traffic lights to move every vehicle from its entry to its exit before time runs out, without exceeding the budget.
The game focuses exclusively on the traffic management and road-building aspects of Cities: Skylines (specifically CS2), without the city-building overhead.

## 2. Core Pillars

1. **Readable**: Every lane, connection, and movement must be legible at a glance.
2. **Forgiving**: Slightly unrealistic slope and clearance values are acceptable if they make building easier.
3. **Deterministic**: Same level + same build = same result. Seeded RNG, fixed timestep.
4. **Fast to iterate**: Build → Play → Fail → Edit in under a minute.

## 3. Technical Stack & Constraints

- **Engine**: Godot 4.4+ (Standard, not .NET)
- **Language**: GDScript
- **Platform**: Offline PC (Windows) primary target.
- **Simulation Rate**: 60 Hz fixed step, render-decoupled.
- **Max Vehicles**: 200.
- **Driving Side**: Right (US).
- **Terrain**: Flat ground; terrain features exist only as blockers around the play area.
- **Road Elevation**: Ground, elevated (overpasses), and sunken (underpasses with retaining walls). Maximum grade: 10%. Min clearance: 5.0m.
- **Constraints**: Zero budget, no international payments (based in Nepal). All tools, assets, and services must be free. AI is doing all coding.
- **Assets**: Kenney (CC0) kits for vehicles and props. Flat stylized materials.

## 4. Architecture Summary

### Core Graph

- `RoadGraph` (Autoload): Owns `nodes: Array[RoadNode]` and `segments: Array[RoadSegment]`.
- `RoadNode`: A position, a list of attached segment ends, and flags (`is_entry`, `is_exit`, `is_waypoint`, `forced_junction`).
- `RoadSegment`: A `Curve3D`, a `RoadType`, `start_node`, `end_node`, and a stable `uid` integer.

### Road Types

- Defined by a `lane_layout_string` (e.g., "FB", "FFBB", "FFFF").
- Lane index 0 is the rightmost lane when facing forward. Lanes are generated by offsetting the centerline `Curve3D` by the lane width.

### Lane Graph

- `LaneGraph` (Autoload): Builds `lanes` and `arcs` on every graph change.
- `Lane`: A single lane along a segment. Has `from_node`, `to_node`, `direction` (F/B), and a lateral `curve`. Lanes are trimmed at junctions based on an angle-based formula (max 5.0x lane width).
- `LaneArc`: A directed connection between two lanes. Has a Bezier curve, `length`, `enabled` flag, and `conflicting_arcs`.

### Routing

- `LanePathfinder`: A\* on the lane graph. Penalizes lane changes. Used to determine the sequence of lanes a vehicle traverses.

### Simulation

- `VehicleManager`: Spawns vehicles, computes occupancy (leader/follower lookup), handles IDM car-following, MOBIL lane changes, and junction arc reservations.
- `Vehicle`: Holds a `path: Array[PathStep]`, speed, and step index. Moves kinematically along the curves. No physics bodies.

### Junction Arc Generation Algorithm

- `LaneArcAlgorithm`: The custom algorithm that assigns lane-to-lane connections at junctions.
  - Phase 1: Init promise matrix (U-turn = -1, Soft-forbid = -2).
  - Phase 2: Iteratively add commits based on surplus.
  - Phase 3: Order exits clockwise, spread lanes, and assign specific lane indices.
- `LaneArcBuilder`: Wraps the algorithm. Extracts groups, runs the algorithm, returns candidate arcs. Only arcs returned by the algorithm are enabled by default; others are created but disabled for manual override.
- **Pass-throughs**: Treated by the algorithm. Strict 1-to-1 matching is no longer hardcoded; the algorithm handles them based on lane counts.

### UI / Tools

- `RoadBuilder`: The main build tool. Handles drawing straight roads, C-curves, S-curves, demolishing, reversing, and road type updates. Integrates snapping.
- `SnapResolver`: Resolves cursor to nodes, lanes, segments, or guidelines.
- `JunctionEditor`: Shift-click a pass-through to promote it. Drag entry/exit dots to toggle lane arcs. Panel with "Clear all" and "Reset to default".
- `MainToolbar`: Tool selection, road type dropdown, road shape dropdown (Straight/Curve/S-Curve), snapping toggle, level data toggle.

## 5. Saved Format

Levels are saved as JSON in `user://levels/`. Contains: version, bounds, budget, time_limit, blockers, fixed_roads, props, demand matrix, and `vehicle_order`. Arc overrides are stored in `ArcOverrides` and serialized alongside the level.

## 7. Rules for the AI

- **Do not guess the code state.** Always ask for the file contents if there is a parse error or if a patch depends on code not shown in the context.
- **Provide full functions, not snippets**, when modifying more than a few lines.
- **Break changes into small, testable phases.** Do not generate 5 large files at once.
- The user is a computer engineering graduate and understands math/code, but wants to focus on design and testing. Explain the _why_ before the _code_.
- When the game breaks (parse errors or crashes), guide the user through clearing the `.godot/` folder and restarting Godot.
- **Git**: The user uses Git. Always provide a commit message after a successful set of changes.
